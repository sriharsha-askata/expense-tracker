# Roadmap — Personal Expense Tracker

Status: **v0.2 — revised 2026-11-19 (IST)** to the Product Owner's local-first Android direction (see `PRD.md` changelog). Aligned to the brief's 6 phases. **Phase 3 starts only when the Product Owner explicitly says it may.**
No dates are committed; slice sizes are in `docs/development/BACKLOG.md`.

## Rules (revised)
1. **Tests passing ends engineering for a phase.** A phase's engineering is done when its automated tests pass in CI (headless, on every PR). Nothing about a calendar dogfood, a speed measurement on a real phone, or an AI accuracy number blocks writing code for a later phase.
2. **A 2-week dogfood gates "safe for daily use" (v1.0)**, not development. It is run by the Product Owner on a real phone from a cloud-built APK.
3. **Definition — correctness defect:** any **wrong total** (a figure that isn't the exact sum of its line items), any **wrong date or month placement**, any **lost entry**, any **duplicated entry** (including after sync, restore, crash or retry), or any **silent overwrite** of an edit. "0 correctness defects" in the dogfood means none of these was observed or reported.
4. **Remote-only testing.** The Product Owner installs no Android Studio or local toolchain. CI runs on every PR; installable Android APKs come from on-demand EAS cloud builds (`workflow_dispatch` or release tag), **not** on every PR. Expo's published free tier allows **15 Android builds per calendar month** (low-priority queue; quota resets monthly); the workflow says so when it runs out rather than silently paying. Expo Go is not an acceptable stand-in. Expo account and token are the Product Owner's to provide, never in the repo.
5. **Performance numbers are targets**, measured on a real phone during the dogfood; they are not CI blockers.
6. **AI is not scheduled** and is not part of v1.0. It is a later, optional, confirm-only phase (Phase 5), started only on the Product Owner's explicit go-ahead. Missing the AI accuracy bar switches AI off; it never blocks or rolls back the ledger.

## Post-MVP (re-prioritised with the PO after 4–6 weeks of real use)
- **P1:** app lock (AUTH-8), recurring transactions (TXN-8), CSV/Excel import with dedupe (IMP-1), accounts & transfers (TXN-9, ends card/EMI double-count risk), budget notifications (BUD-5), iOS build (PLAT-1) from the same project, AI edit/delete with confirmation (AI-7), multi-expense messages (AI-8), monthly AI summary (AI-9).
- **P2:** multi-currency (TXN-10), splits (TXN-11), receipt OCR (IMP-4), savings goals (GOAL-1), budget recommendations and anomaly detection (AI-10/11), PDF reports, sub-categories.
- **Future (only with validated demand + privacy review):** household/shared ledgers (HH-1), bank statement/SMS/Account Aggregator import (IMP-2/3).
- **Removed from the old roadmap:** email/push alerts as a hosting prerequisite, Google sign-in/2FA, web app, offline mode (now built in), Indian FY (moved into MVP), server backups.
